# 通过学校拿钱：四条现实路径与行动清单（配合软著）

> 你的计划：**先拿软著证书 → 再通过学校这边拿到钱**。这个顺序是对的，但钱从哪来、要准备什么、
> 什么时候该签什么文件，四条路径差别很大。本文按"离你最近 → 需要主动争取"排序，并给出可直接执行的动作。

---

## 先记住三条铁律

1. **软著是"票"，不是"钱"**：软著证明"这是你开发的软件"。钱来自**学校的奖励政策 / 项目经费 / 竞赛奖金 / 横向合同**，
   软著是这些路径的**支撑材料与前置条件**。
2. **登记前想清楚权属**：一旦以"学校独占"（C 方案）登记，之后你个人拿它接商业项目就要学校同意。
   要"既能拿证又能收钱"，选 **B（个人独有 + 学校免费使用）** 或 **B+（校内免费、校外商用归你）** 或 **D（共有）**
   —— 三份文本已生成在 `软著申请材料/权属文件/`，按学校要求挑一份签。
3. **动作顺序**：先问政策 → 再决定权属 → 再登记 → 再拿材料去申请奖励/立项。**不要在登记前把源码公开发布**
   （论文附源码、GitHub 公开等），否则可能影响"未发表"状态与新颖性主张。

---

## 路径一：学校科研成果 / 知识产权奖励（最直接）

**是什么**：不少高校对授权的软著给**现金奖励**（金额从几百到几千不等），走科研处 / 科研与研究生工作处。

**你要问的一句**：**"我校学生（本科）获得软件著作权，有没有对应的成果奖励或学分认定？依据哪个文件？"**

**要准备**：软著登记证书（或受理通知书）复印件 + 学生证 + 申请表（科研处提供）。
**注意**：多数学校的奖励政策是**面向教职工**的，学生能否同等适用需**看文件原文**；
我这边的核查结果是：学校官网科研处「科研制度」栏目只挂了国家/省级文件，**没有公开的校级知识产权奖励办法**
→ 必须当面问（学院教学秘书或科研秘书最快）。

---

## 路径二：大创项目 / 创新创业立项（把系统装进项目里）

**是什么**：大学生创新创业训练计划（国家级/省级/校级）有**经费**（校级常见 1000–5000 元、省级上万），
结题后可评优、也可作为论文与竞赛的支撑。我们学校 2026 年获批过 48 项国家级/省级大创（创新创业栏目可见）。

**为什么适合你**：本系统功能完整、可演示、已属于"教育信息化 / 校园数字化"方向，**非常适合包装成"智慧校园微应用"类大创题目**。

**动作**：
1. 找学院负责大创的老师确认**下一批申报时间**（通常每年 3–5 月，以当年通知为准）；
2. 用现成材料成稿：`README.md`（功能清单/权限矩阵/技术亮点）→ 项目书正文；
   `宣传截图/`（11 张图）→ 项目书插图与答辩 PPT；`对外合作/与同类系统对比与优势说明.md` → "创新点"章节；
3. 结题材料里附**软著证书**，是加分项（也能算成果）。

---

## 路径三：学科竞赛（奖金 + 荣誉，最"体面"的拿钱方式）

**是什么**：中国国际大学生创新大赛（原"互联网+"）、"挑战杯"、中国大学生计算机设计大赛、蓝桥杯等，
校级/省级/国家级都有奖金与综测加分（我们学校 2025 年计算机类竞赛国家级 247 项、省级 940 项）。

**为什么适合**：你有**可运行的真实系统 + 演示数据 + AI 能力 + 完整的软著材料**，这在"软件应用赛道"里是完整故事。

**动作**：
1. 挑最近的比赛（问学院竞赛负责人或看学院官网通知），通常 3–5 月校赛、6–8 月省赛；
2. 15 分钟演示脚本我已给过（`README.md` 演示路径），PPT 直接用 `宣传截图/` 的图；
3. 报名时**著作权人写你自己**，别写成学校——否则你个人拿奖的资格与后续商用都会被绑住。

---

## 路径四：横向课题 / 校内立项（金额最大，也最慢）

**是什么**：学院或学校真要用这套系统时，常见两种形式：
· **横向技术服务合同**：由学校（甲方）与你（作为技术服务方/团队）签，经费进学校账户，按学校横向经费管理办法提取劳务/绩效；
· **校内信息化立项**：学校把"班级管理模块"列入年度信息化建设，走采购/开发经费。

**为什么可行**：本系统的定位正是"班级层微应用、不替代现有系统、零运维"，与学校"十五五"打通数据壁垒的思路一致
（见 `集成方案/与学校现有系统集成方案.md` 的对接清单——拿去和信息中心谈，会显得专业）。

**动作**：
1. 先做一次**小范围试点**（一个班 + 一位辅导员 + 一位任课教师，跑一个学期），留使用记录；
2. 用试点数据去谈：单校授权合同模板已备好（`对外合作/软件许可合同（单校授权版）.docx`）；
3. 若走横向，**先签合同再交付**，合同里写明著作权归你、许可范围、维护期与费用。

## 现在就开始做（今天就能完成的 3 件事）

- [ ] **问政策**：给学院教学秘书/科研秘书发一句话——"我拿到软件著作权后，学校对学生成果有没有奖励或学分认定？依据哪个文件？"（附软著证书扫描件）
- [ ] **定权属**：从 `软著申请材料/权属文件/` 选 B 或 B+ 打印，找学院盖章（这一步决定你后面能不能自己收钱）
- [ ] **做演示材料**：`宣传截图/` 挑 6 张 + `README.md` 的功能清单，压成一份 PDF 一页纸（可发微信给老师）

## 常见坑（我见过的真实情况）

| 坑 | 后果 | 规避 |
| --- | --- | --- |
| 登记时把著作权人写成学校（C 方案） | 后续你自己商用/许可需学校同意，收益要谈 | 走 B/B+/D；若学校坚持，要求在许可文件里写清"校外商用归开发者" |
| 登记前把源码公开到 GitHub | 可能影响"未发表"状态；也失去谈判筹码 | 先登记，后公开；论文附录放"功能截图 + 核心代码片段"即可 |
| 口头承诺"学校用不收钱" | 以后学校卖给别的学院也与你无关 | 签书面许可（期限/范围/是否可转授/署名），一页纸即可 |
| 只报"软件"不报"成果" | 学校系统里查不到你，奖励走流程走不通 | 拿到证书后**主动登记到学院/科研处成果库** |
| 论文里写了"学校委托开发" | 与"独立开发"的权属主张矛盾 | 论文写"独立完成"，与软著申请表的"单独开发"保持一致 |

## 一句话口径（跟老师/学院谈时用）

> "这套系统是我独立开发的毕业设计，已经拿到软件著作权（著作权人是我本人），
> 学校用是**免费**的——只要一页使用许可就行。如果能进学校的项目或立项，我可以按学校要求做适配与维护，
> 著作权仍归我个人，这样对学校零风险、对我也是激励。"

这段话同时说清了：**零成本、零风险、免费使用、边界清楚**——最容易谈成。
