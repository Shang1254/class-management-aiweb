# 晴川学院班级管理系统 · 与同类系统对比与优势说明

> 用途：论文「系统比较分析」章节素材 / 答辩答辩页 / 面向学院与同类院校的介绍材料
> 口径说明：下表中"其他系统"的能力按其**公开产品定位**归纳，均为常见形态；本系统一栏全部为**已实现并可当场演示**的功能（括号内为对应模块）。

---

## 一、五类"班级管理"相关系统的定位差异

| 类型 | 代表 | 它擅长什么 | 班级这一层缺什么 |
| --- | --- | --- | --- |
| 家校沟通类 | 班级小管家、晓黑板、钉钉家校 | 通知触达、打卡上报、家长沟通 | 无成绩分析、无综测、无奖助评审流程、无岗位权限体系；数据在厂商云 |
| 校级教务系统 | 正方等教务平台（本校在用） | 课表、成绩、学籍、教学任务（**校级、面向管理层**） | 班级级执行层：请假核销、考勤台账、健康与安全、奖助过程、综测排名都不覆盖 |
| 课程内容平台 | 学习通、智慧树（本校在用） | 课程资源、课堂签到、作业与测验 | 与班级管理无关：无奖助、无健康日报、无综测、无学工线 |
| 通用班级管理系统（项目型/买断） | 各类定制开发 | 功能相对全 | 需服务器与运维、定制周期长、报价高；小规模使用"杀鸡用牛刀" |
| **本系统** | 晴川学院班级管理系统 | **班级级执行 + 学工/教学双线闭环 + 可选本地大模型**，零部署 | 见第四节"已知边界" |

## 二、逐项能力对比

| 维度 | 家校类 App | 教务系统 | 学习通/智慧树 | 通用定制系统 | **本系统** |
| --- | --- | --- | --- | --- | --- |
| 部署成本 | 免费/依赖厂商云 | 校级采购 | 校级采购 | 服务器 + 运维 + 定制费 | **零部署**：双击 `index.html` 即用，或放静态站点（教学线可见） |
| 学生档案（含专升本/自考助学等学情） | 简单名单 | 有但不面向班级 | 无 | 有 | **有**：培养层次 × 招生类别 × 学习形式 + 学制/届别自动推算 |
| 成绩管理 | ✗ | 录入为主 | ✗ | 有 | **批量录入 + 总评合成（平时 60%+期末 40%）+ 排名 + 成绩单打印 + 按学期统计/GPA** |
| 成绩分析 | ✗ | 弱 | ✗ | 部分 | **分数段/趋势/雷达/班级对比 + 断网降级图表** |
| 课堂考勤与签到 | 打卡（非课堂） | ✗ | 签到码 | 部分 | **签到码限时签到 + 逐个/批量录入 + 按工作日联动请假** |

| 请假审批 | 申请表单 | ✗ | ✗ | 部分 | **在线申请→审批→自动按工作日写入考勤（跳过假期/计入调休）** |
| 健康与安全（学工线） | 打卡上报 | ✗ | ✗ | 少见 | **每日体温填报 + 实时定位（省市区街道四级）+ 校外动向专区 + 未报/异常名单** |
| 奖助学金管理 | ✗ | ✗ | ✗ | 少见 | **国家/校级奖助全流程记录（金额/学年/评审状态）+ 真实标准 + 学生端可见** |
| **综合素质测评** | ✗ | ✗ | ✗ | 多为空白表格 | **自动算分排名**：智育 60（平均分×0.6）+ 德育 20（缺勤/迟到扣分）+ 文体附加 20（竞赛加分 + 手工加减分），一键导出公示表，学生端可查明细 |

| 岗位分线（教学线/学工线） | ✗ | 仅功能权限 | ✗ | 少见 | **角色 × 岗位双维度**：教师≠辅导员各看各的，辅导员兼课可勾选"兼任授课" |
| 敏感信息分级 | 家长手机号可导出 | 视配置 | ✗ | 弱 | **家长电话仅辅导员/管理员可见**，教师端与导出均剔除 |
| 数据边界 | 厂商云 | 校级服务器 | 厂商云 | 自建服务器 | **数据留在使用者本机/校内；可选本地大模型（数据不出校）** |
| AI 能力 | 无或仅客服 | 无 | 有限 | 多为"接一个云 API" | **云 API / 本地 Ollama / 离线模板三档可切换**；通知起草、学情简报、值班日报、学业帮扶、出题、办事指引、政策问答；**敏感信息先脱敏**、AI 只出草稿 |
| 运维 | 依赖厂商 | 信息中心 | 依赖厂商 | 需要运维 | **无后端、无数据库、单文件级备份（JSON 导出即可微信发送）** |
| 可迁移/合规 | ✗ | ✗ | ✗ | ✗ | **源码与文档齐全（含软著三份材料）**；预留后端演进方案（18 张表 Supabase 脚本） |

## 三、本系统的六个差异化亮点（答辩可直接讲）

1. **把"班级执行层"做实**：校级系统管记录，本系统管"今天谁没来、谁该谈话、谁该交材料"——请假按工作日写考勤、健康日报带定位与校外动向、学业预警三视角，都是班主任务实场景。
2. **综合素质测评自动化**：同类系统大多只给一张空白表格，本系统按"智育 60 + 德育 20 + 文体附加 20"从成绩/考勤/竞赛**自动算分并排名**，辅导员还能录入手工加减分，一键导出公示表——这是奖助与评优的第一依据。
3. **岗位分线，而不是功能权限**：教师端只有"授课要用的"（我的课程、成绩、作业、测验），辅导员端只有"学生工作"（综测、奖助、健康、考勤月报、请假）；辅导员兼课才开通教学线。敏感信息也按线分级（家长电话仅辅导员可见）。
4. **零部署 + 断网可用**：任何一台教室电脑双击即用；断网时天气隐藏、图表降级、AI 走离线模板，演示与使用都不翻车。
5. **本地大模型可选项**：学校在意数据合规时切"本地 Ollama"，学生数据不出校内、无调用费；不在意时切云端小模型，质量更好。同一套界面，一个下拉框切换。
6. **可对接而非替换**：用教务导出文件（成绩单/课表 CSV）做导入，不碰学校统一认证与数据接口——定位是校园信息化生态的**补充层**，而不是竞争系统。

## 四、已知边界（如实说明，也写进论文"局限与展望"）

- **单机形态**：当前数据存浏览器本地，适合一位老师/一个班或一个学院内各自使用；多人跨设备协同需按《后端演进》迁移到中心化后端（脚本已备好，18 张表一一对应）。
- **无家长端与原生 App**：家校触达依赖通知与手机推送（ntfy）与导出的表格；如需家长端属下一阶段。
- **课表/成绩以教务导出为准**：不做教务直连（合规与授权边界），导出文件导入已覆盖 90% 场景。
- **AI 输出需人工确认**：定位为"草稿与建议"，不自动写入成绩或评价，符合教育场景的可解释与责任要求。

### 一句话总结（可直接用于答辩结尾）

> 教务系统记录"教与学"，本系统补齐"班级怎么运转、人怎么被照顾到"：从考勤、请假、健康到奖助、综测、预警，全部落在班级这一层，零部署、可断网、数据可留校内，还能接本地大模型。
