# 晴川学院班级管理系统

一个面向**武汉晴川学院计算机学院**班级管理场景的纯前端系统：HTML + CSS + JavaScript，数据保存在浏览器 `localStorage` 中，**无需后端、无需安装任何依赖**，双击 `index.html` 即可使用。

## 项目背景与意义（论文绪论素材）

**学校与学院概况（数据来源：学校官网 www.qcuwh.cn、计算机学院官网 jkx.qcuwh.edu.cn 与学生工作处官网 xgc.qcuwh.edu.cn，2026 年 10 月查阅）**：

- **武汉晴川学院**：前身为 2006 年经教育部批准设立的武汉大学珞珈学院，2016 年转设为独立设置的应用型普通本科高校并更名；办学定位"应用型、区域性、特色化"，**校训「明体达用、抱璞开新」**；现有 9 院 1 部、33 个本科专业，在校生近 1.5 万人，硕士、博士学历教师占比约 95%；校址位于武汉市东湖新技术开发区中华科技产业园玉屏大道 9 号。
- **计算机学院**（本系统的试点学院）：在校生 1700 余人，专任教师 68 人（含 5 名教授、11 名副教授、1 名高级工程师）；建有"现代计算机实验实训中心"（2568㎡、16 间分实验室，覆盖嵌入式系统、物联网、大数据虚拟仿真、人工智能等方向）；开设**计算机科学与技术（鸿蒙科创班）、软件工程、数据科学与大数据技术、人工智能（中软国际班）** 4 个本科专业与计算机应用技术、软件技术 2 个专科专业；学科竞赛累计获国家级奖项 247 项、省级以上 940 项，2025 年全国计算机类竞赛民办高校排名第 12、湖北省第 1。
- 试点班级为 **计科20252302班（计算机科学与技术·专升本）**，系统内该班的课程、课表、成绩单均为**演示教务数据导入**（详见「示例数据说明」与「教务系统对接」章节）。
- **奖助体系**（学生工作处口径，系统内「奖助管理」模块按此建模）：国家奖学金 10000 元/人（本科生 17 名、专科生 1 名，专升本自本科第二年起可申请）；国家励志奖学金 6000 元/人（面向品学兼优的家庭经济困难学生）；国家助学金按困难等级分档；校级设**晴川奖学金甲/乙/丙等（3000/2000/1000 元）与晴川助学金甲/乙等（1500/1000 元）**。评选流程为"学生申请 → 学院初评 → 学校竞评/公示 → 发放"，公示期不少于 5 个工作日（详见学工处官网通知）。

**痛点分析（现状调研）**：目前学院各班级的日常管理主要依赖三种彼此割裂的方式——辅导员/班主任手中的 Excel 表格、微信群/QQ 群的通知刷屏、以及面向学校管理层的教务系统。由此带来四个突出问题：

1. **信息分散**：学生档案、成绩单、考勤表分散在不同表格与聊天记录中，无法联动查询，找一个学生的信息要翻多个文件；
2. **统计靠手工**：算平均分、排名次、统计出勤率全靠人工处理，效率低、易出错、无法及时反映班级动态；
3. **权限缺失**：学生无法安全便捷地查看自己的成绩与考勤，任课教师/班主任也缺少一套边界清晰的管理工具，敏感信息（全体成绩、家长电话）容易在群聊中误传播；
4. **数据易丢失**：本地 Excel 没有备份与审计机制，误删、误改即永久丢失，且无法追溯是谁改的。

**解决方案**：本系统针对上述痛点提供班级、学生、成绩、考勤、请假、通知的一体化管理，采用管理员/教师/学生三级角色权限隔离（教师数据严格限定其任教班级、学生只读本人数据），学生档案按真实教务口径覆盖**培养层次（本科/专科）× 招生类别（普通高考/专升本/自考助学）× 学习形式（全日制/非全日制）**多类型学情——其中专升本属统招全日制，助学班属非全日制自考，内置成绩分析可视化（趋势/雷达/班级对比）、按学年学期统计、请假审批流、考勤月报预警、操作审计日志与数据备份恢复。

**意义**：一是把班主任从手工统计中解放出来，异常考勤和成绩波动自动浮现；二是让学生第一次拥有安全查看个人数据的入口；三是纯前端架构零部署成本——任何一台教室电脑双击即用，为同类院校班级提供了一套低成本、可复制的数字化管理方案。

## 一、运行方式

1. 直接**双击 `index.html`**（推荐使用 Chrome / Edge 等现代浏览器）。
2. 如果浏览器限制了 `file://` 下的部分功能，也可以启动一个本地静态服务器，例如：
   ```bash
   # 方式一：Python（一般系统自带）
   python -m http.server 8080
   # 方式二：Node
   npx http-server -p 8080
   ```
   然后访问 http://localhost:8080

**学期与届别口径（按武汉晴川学院官方用法：学校首页用「2026级新生」记入学年，学工处通知用「2026届毕业生」记毕业年）**：

- **学制**：本科 **四年**、专科 **三年**、专升本（本科段）**两年**（`Store.PROGRAM_YEARS`）；**届 = 入学年 + 学制**；
- **专升本的同届关系**：专升本学生与「入学年 − 2」的本科年级同届毕业——2025 年入学专升本 ↔ 2023 级本科，均为 **2027 届**（系统文案中显式标注"与 2023 级本科同届毕业"）；
- **学期显示**：学生与辅导员视角的学期文案附**学期序号与总学期数**（总学期数 = 学制 × 2：本科 8 / 专科 6 / 专升本 4），如专升本学生看到的「2026—2027学年 第一学期（第三学期·共四学期）」，2023 级本科看到的「（第五学期·共八学期）」；
- **显示位置**：侧边栏页脚（学生本人 / 辅导员所带班级）、学生端「我的信息」的"年级 / 学制 / 届别"栏、辅导员学工工作台副标题、学生管理列表的"层次·类型·届别"列、班级管理列表的"学制 / 届别"列、学生列表 CSV 导出（含学制与届别两列）；
- **示例**：计科2301班（2023级 · 本科四年制 · **2027届**）｜计科20252302班（2025级 · 专升本二年制 · **2027届**，与 2023 级本科同届）｜助学软件2501班（2025级 · 专科三年制 · **2028届**）。

| 全部学期 | `全部 3 个学期（跨学年）` | **跨学年**合计（把系统里全部学期一起算，会横跨多个学年，tooltip 已说明） | 需要看历史全程时 |

实测（林一舟演示成绩单）：第一学期 平均分 80.2 / GPA 2.83 / 12 门；第二学期 89.7 / 3.80 / 12 门；**全学年 84.9 / 3.33 / 24 门**（= 两学期合计）；综测：第二学期 73.8（第 4 名）→ 全学年 70.9（第 7 名，智育＝学年平均分 84.9 × 0.6）。文案也随维度切换（"本学期有 1 门不及格" ↔ "本学年有 1 门不及格"）。

**「全站学期」的可用性细节（持续打磨）**：⓪**全站学期下拉统一渲染**（`UI.termFilter.optionsHTML()`）——顶栏、成绩管理、成绩分析、我的成绩、我的综测、综合素质测评、学业预警、班级对比报告、AI 帮扶跟踪**共用同一套选项文案与标记**（含「本 ·」标记、学生视角的届别学期序号、可选"全部学期（N 个学期合计）"），不再各页面各自拼接、显示不一致；①「全部学期」选项标注**学期数量与范围**（如「全部 3 个学期（跨学年）」），tooltip 说明会跨学年混合统计；②页面内学期下拉与顶栏**双向同步**（成绩管理、成绩分析、我的成绩、综测、帮扶跟踪…改任一处，另一处与全站偏好同时更新）；③**学期智能回退**：当所选/当前学期没有数据时，自动回退到该生/该班**最近有成绩的学期**，并用下拉下方一行小字说明原因（不重复显示学期名，保持界面整齐）；④综合素质测评按学期独立计算、**不提供“全部学期”**（综测不能跨学期合计，这是口径要求）；⑤**选项按学年成组、时间顺序不打乱**——每个学年的「合计」项紧跟它自己的各学期（此前所有合计项排在所有学期之前，会出现「2026-2027学年（全学年）」排在「2025-2026学年第一学期」前面这种时间线来回跳的读法）；⑥**学生视角的届别学期序号统一标注**（第 1、2、3 学期都标；此前只标第 3 学期及以后，导致「我的第一学期是哪一行」找不到）；⑦**失效值护栏**：全站学期值若已不再可用（如上一版本选过的「本学年（全学年）」），读取时自动清掉并回落到默认口径，避免下拉显示与统计口径不一致。⑧**每个有学期概念的页面都真正跟随学期**：我的考勤（考勤记录与请假记录）、我的作业、随堂测验此前“点了没反应”——现按记录所属学期筛选（作业与测验没有学期字段，按其**截止时间所属学期**推算），并在工具栏显示「统计范围：X」；**进行中 / 待作答的条目始终显示**（待办不能被筛选藏起来，否则会误事）；⑨**与学期无关的页面把顶栏选择器置灰并标「本页不适用」**（当期待办、今日数据、静态资料、名册与配置类页面），悬停有说明——不再让用户点了没反应而以为系统坏了；⑩**奖助管理跟随学年维度**（奖助记录按学年归档）：统计 chips 与列表同口径，并显示「统计范围 2025-2026 学年」；⑪我的综测的兜底提示改为按口径措辞（“综测按学期计算（不跨学期合计）；当前口径下没有成绩数据，已显示最近有成绩的学期：…”），不再出现选了“全部学期”却提示“本学期暂无成绩数据”这种与所选不符的文案。⑫**两个"合计"维度改名为能区分范围的说法**——原来「全部学期（3 个学期）」与「2025-2026学年（全学年）」读起来都像"全部都算上"，用户直接问「全部学期跟全学年难道不是一个意思吗」；现在改成「全部 3 个学期（跨学年）」与「2025-2026学年（2 个学期合计）」，tooltip 分别写明"跨学年合计"/"不跨学年"；⑬**我的成绩新增口径说明条**：所选范围里若有学期暂无本人成绩，页面直接写出来（如「范围共 3 个学期；2026-2027学年第一学期 暂无你的成绩，未计入统计。」）——否则「全部学期」与「学年合计」会给出同一组数字，看起来仍像同一个选项。

**顶栏「全站学期」切换器**是全站唯一的学期入口：仪表盘、成绩管理、成绩分析、我的成绩、班级对比报告、学业预警都跟随它筛选，页面内的学期下拉与顶栏双向同步（写同一个偏好 `cms_ui_term`），不会出现"顶栏选了学期、页面数字不动"的情况。弹窗支持 **Esc 关闭**、打开时焦点自动移入、关闭后焦点归还，并临时锁定页面滚动。

**安全设计（可作为论文素材）**

1. **密码摘要存储**：密码不保存明文，使用 Web Crypto API 计算后只存 SHA-256 摘要（64 位十六进制）；旧版本明文密码在登录成功时自动升级为摘要。
2. **登录防爆破**：连续失败 5 次锁定账号 5 分钟，锁定期间拒绝登录并提示剩余时间。
3. **审计日志**：登录成功/失败/退出及所有数据增删改均自动记录操作人、角色、时间、模块与详情，日志上限 1000 条滚动存储。
4. **权限隔离（RBAC）**：管理员/教师/学生三级角色，教师数据严格限定其任教班级（支持跨班任教）、学生只读本人数据，前端每处查询均按角色范围过滤；外聘教师聘期到期自动拦截登录。
5. **会话管理**：登录会话 12 小时自动过期（机房 / 共用电脑场景防会话残留），过期后需重新登录。
6. **敏感信息分级**：学生家长电话仅**辅导员与管理员**可见，任课教师端列表显示"仅辅导员可见"、CSV 导出同样剔除——对应"谁负责家校沟通、谁能看到家庭联系方式"的现实分工。
7. **岗位线收口**：教学线（授课工具）与学生工作线（行政与学生事务）互不重叠；辅导员**兼课**时由管理员勾选"兼任授课"按需开通教学线，避免"人人拥有全部功能"。

**数据可视化说明**：成绩分析页图表基于 [ECharts 5](https://echarts.apache.org/)（CDN 引入，`index.html` 中有注释）。断网或 CDN 不可达时自动降级为内置 CSS 条形图/统计表格，所有统计功能不丢失。

**与学习通 / 智慧树的能力对标**（论文"系统比较分析"素材）：学校现用学习通、智慧树两个平台，本系统在其核心的**课堂管理场景**上实现同能力等级的替代方案——

### 与武汉晴川学院教务系统的数据对接（论文「系统集成」素材）

**学校信息化生态现状**：武汉晴川学院采用**正方软件**的统一身份认证平台（CAS 单点登录，`ca.qcuwh.edu.cn`）作为全校身份入口，校园门户（`portal.qcuwh.edu.cn`）聚合教务、学工、一卡通等业务系统；本系统在登录页与页脚提供了**校园门户入口链接**，方便师生跳转学校统一认证。

**三种对接方式的取舍分析**（论文可直接引用）：

| 方式 | 可行性 | 说明 |
| --- | --- | --- |
| A. 直连教务接口（SSO/数据交换） | ❌ 超出边界 | 需学校信息中心授权 + 服务端完成 CAS 票据校验（浏览器跨域限制）+ 凭据安全管理，纯前端应用无法安全实现；未授权对接属违规 |
| B. **教务导出文件导入** | ✅ **已实现** | 师生在正方教务系统自助导出成绩单与课表，经本系统「数据管理 → 教务数据导入」**直接选 .xlsx/.xls/.csv 文件（或粘贴文本）即入库**（列名自动识别、覆盖式同步；读取文件后自动进入预览）。针对正方系各高校的导出形态做了兼容：**课表支持「周课表矩阵」**（表头 节次 + 星期一…星期日，单元格自动拆分课程/教师/地点/周次，多门课给出提示）与长表两种形态；**成绩单支持「学年 + 学期」分两列自动合并**、无「考试名称」列时按「总评」记录、学期支持 `2025-2026第一学期` / `2025—2026-2` 等写法；两种情况都可指定「默认班级 / 默认学期」兜底 |
| C. 预留接口层 | ✅ 已预留 | `Store.syncFromEdu()` 为服务端直连的预留入口，将来学校开放授权接口时在**后端**实现真实同步，前端结构无需改动 |

| 数据 | 获取方式（正方教务） | 导入路径 |
| --- | --- | --- |
| 课表 | 信息查询 → 课表查询 → 导出（.xls/.csv） | 数据管理 → 教务数据导入 → 课表（**周课表矩阵**与长表均可；节次支持 `1-4节` 区间与 `第7节` 单节自动展开；支持上课周次；矩阵形态可从文件标题识别班级，或用「默认班级」指定） |

| 学生名单 | 学籍名单 → 导出 | 数据管理 → 学生批量导入（既有功能） |

**UI 设计语言（「川大·藏青金」学术风，论文「界面设计」章节素材）**：

1. **品牌意象**：深藏青（学术庄重）为主色、鎏金为荣誉点缀——侧边栏藏青渐变、导航选中态金色光条、统计卡片使用"藏青/鎏金/晴空蓝/墨绿/绛红/黛蓝"六色学院色板，排名前三名以金/银/铜底色标识。
2. **校园实景登录页**：全屏校园照片（取自学校官网公开图集，已压缩至 1920px 并剥离含 GPS 的 EXIF 信息）+ 深藏青渐变遮罩 + 官方白色校名标 + 缓慢推近的 Ken Burns 镜头动画；登录卡为深色玻璃拟态配金色流光描边（CSS mask 镂空技术）。每次进入登录页在校园全景与校门两张照片间随机切换；图片缺失时自动回退为深蓝渐变，不影响使用。
3. **双主题系统**：全部颜色收敛为 CSS 变量，`html[data-theme="dark"]` 一组变量覆盖即完成深色模式；支持手动切换（持久化到 localStorage）并默认跟随系统 `prefers-color-scheme`；ECharts 文字/网格配色随主题注入，切换主题自动重绘当前页。
4. **玻璃拟态与层次**：应用内卡片采用半透明底 + `backdrop-filter` 毛玻璃 + 双层阴影，页面背景叠加品牌色光斑。
5. **微交互**：路由切换卡片级联淡入（stagger 动画）、统计数字从 0 滚动到目标值（MutationObserver 无侵入实现）、登录页打字机标语、表格行悬停高亮、Toast 弹性滑入、错误提示抖动动画；并尊重系统"减少动态效果"偏好（`prefers-reduced-motion`）。
6. **响应式**：桌面侧边栏布局 / 移动端抽屉导航（≤900px），登录页大屏左右分栏品牌区（≤1080px 自动隐藏），表格横向滚动适配窄屏。
7. **「教务案头」版式语言（登录后界面的原创设计体系）**：
   - **单字印章导航**：侧边栏每个菜单项以描边小方印承载一个汉字（览·班·生·绩·析·勤·报·告·众·志·存·设 / 档·卷·迹·闻），选中时鎏金印泥填充——取代千篇一律的 emoji 图标；
   - **日历牌 Hero**：仪表盘顶部为“日历牌 + 问候语 + 楷体每日箴言 + 红色方印（晴川教务）”组合横幅，箴言按日期从八条经典语句中轮换，背景为校园实景照片配藏青遮罩与内框金线；
   - **衬线编辑排版**：标题、统计数字、表头统一使用宋体衬线字族，统计卡为“彩色书脊 + 中文标签 + 英文小型大写小注（STUDENTS / AVERAGE…）”的报刊式双语排版；
   - **壹贰叁章节编号**：图表区标题由 CSS 计数器自动生成中文大写序号（`counter(secnum, simp-chinese-formal)`）金印徽标，免手写序号；
   - **公文细节**：卡片四角金色裁切角饰（证书式）、页面底纹为方格稿纸、顶栏常驻衬线时钟胶囊、侧边栏页脚自动推算当前学年学期；
   - **字形化交互**：主题切换按钮用「日/月」字、空状态为虚线圆印中的衬线「空」字、Toast 用 ✓/✕/！/i 圆形字形徽标——全系统无装饰性 emoji。

**Web 技术亮点（面向 Web 方向评审的素材清单）**：

| 技术点 | 系统中的实现 |
| --- | --- |
| 语义化 HTML | 登录/应用双视图结构化标记，表单使用 `label + autocomplete`，弹窗使用 `role="dialog"` |
| 现代 CSS 工程 | CSS 自定义属性（变量）主题系统、`backdrop-filter` 毛玻璃、`mask-composite` 描边镂空、`:has()` 选择器、CSS 计数器自动生成章节编号、`object-fit` 图像适配、CSS Grid/Flex 双布局体系 |
| 动效工程 | 全部动画使用 CSS transform/opacity（合成层友好，不触发重排）；`prefers-reduced-motion` 无障碍适配 |
| 无侵入增强 | 统计数字滚动基于 `MutationObserver` 监听 DOM 变更实现，业务代码零耦合；图片加载失败 `onerror` 优雅降级 |

| 本地持久化 | localStorage 序列化存储、统一数据访问层、日志滚动上限、全量备份/恢复 |
| 打印文档规范 | **业务数据 → 可交付纸质材料的统一渲染管线**：所有打印材料（班级成绩单 / 学业信息卡 / 英文成绩单 / 学年成绩单 / 排名证明）由一组表格原语生成（`infoRow` 信息行、`secRow` 节标题行、`thRow` 表头行、`spanRow` 跨列信息行、`signRow` 落款盖章行、`footRow` 页脚说明行），落在**同一列网格**上；打印时仅显示 `body` 直下的 `#print-area`（其余节点 `display:none`），`@page` 锁定 A4 版心，`thead { display: table-header-group }` 实现长表跨页重复表头，`tr { page-break-inside: avoid }` 防止行被拆断；打印前在弹窗中按纸张外观（`.pr-doc`，与打印规则共用同一份 CSS）预览，所见即所得 |
| 性能考量 | 图片压缩至 1920px/渐进式 JPEG、图表窗口缩放防抖重绘、搜索输入防抖、文件对象 URL 用后释放 |

3. **成绩维度扩展**：支持 150 分制、等级制（A/B/C）、补考重修成绩单独归档（权重总评已实现：成绩管理 → 总评合成，平时/期末权重可调）。
4. **数据导入**：在 CSV 基础上增加 Excel(.xlsx) 批量导入学生与成绩。
5. **消息通知**：接入浏览器 Notification API 或邮件提醒作业/考试安排；已读回执增加未读人员名单导出。
6. **任课精细化管理**：在"任教班级"基础上增加"班级 × 科目"任课关系，支持任课教师只管理自己科目的成绩。
7. **打印/导出报表**：在成绩单基础上增加学生名册、考勤月报的打印样式。
