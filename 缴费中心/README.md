# 班级缴费中心 · 使用说明

> 独立微应用：团费 / 班费 / 活动经费的发布、收缴、催缴、核销、账本与公示。
> 与《班级管理系统》**契约挂接、零耦合**——宿主只提供了一个菜单入口与一个桥接页，
> 本应用自带数据层（`pay_*` 存储）、UI、路由与演示数据，双击 `index.html` 也能独立运行。

---

## 一、两种运行方式

| 方式 | 入口 | 身份 |
| --- | --- | --- |
| **宿主嵌入**（推荐日常用） | 班级管理系统 → 侧边栏「缴费中心」（辅导员/管理员）、「我的缴费」（学生） | 宿主登录身份 + 班级名册按契约自动接入，无需登录 |
| **独立运行**（答辩/演示） | 双击本目录 `index.html`（或宿主页「新窗口独立打开」按钮） | 演示登录：收支管理员（王磊·生活委员）/ 班级成员（名册任选） |

## 二、功能地图

**收支管理员**（默认：管理员 / 辅导员；独立模式为「收支管理员」）

| 页面 | 能做什么 |
| --- | --- |
| 总览 | 应收 / 实收 / 账本结余四张统计卡，进行中费项进度条，操作留痕 |
| 费项 | 发布费项（团费/班费/活动经费，金额以「分」存储）、自动生成应缴名单（幂等）、催缴（AI 文案 + 离线模板 + 复制 + 导出未缴名单）、对账核销（一键入账）、缴费名单（单笔核销 / 退款）、CSV 导出、截止 |
| 账本 | 收入 / 支出流水、记支出（类别 / 凭证 / 经办）、按月与类型筛选、结余、CSV 导出 |
| 公示 | 按月自动生成公示文稿：收入合计、支出逐笔（壹贰叁编号）、**人民币大写金额**、结余；AI 导语可选；复制 / 打印存档 |
| 智能审计 | **只读核验**：11 条审计规则（负结余重放 / 对账缺口 / 重复入账 / 截止后缴费 / 收款超 7 天未核销 / 费项超期开放 / 凭证缺失 / 大额支出 / 删除密集 / 渠道缺失 / 周末入账），逐条给出**证据清单与整改建议**；AI 审计意见（本机 Ollama 生成，离线模板兜底，壹贰编号公文格式）；操作留痕统计（近 30 天谁做了什么）。**审计不修改任何数据** |
| 设置 | 支付网关三预设（演示收银台 / 本机签名服务 / 校园支付网关空预设）、AI（本机 Ollama 自动探测）、重置演示数据 |

**班级成员**（学生）

| 页面 | 能做什么 |
| --- | --- |
| 我的缴费 | 待缴列表、去支付（收银台）、缴费记录 |
| 缴费凭证 | 电子凭证（票据样式 + 大写金额 + 「已核销」红章）、打印 |

## 三、支付网关（三预设，对标宿主 AI 网关的「空预设缝」）

| 预设 | 用途 | 说明 |
| --- | --- | --- |
| `mock` 内置演示收银台 | 默认，零配置 | 浏览器内闭环：下单 → 出码 → 支付 → 验签标记 → 凭证。二维码为**演示二维码**（带水印），无任何资金流动 |
| `local` 本机签名服务 | 演示真实链路 | `python pay_server.py`（或双击 `启动缴费签名服务.bat`，端口 8818）。真实 HTTP：RSA2 签名下单 → 沙箱真二维码 → 2 秒轮询**主动查单**（`alipay.trade.query`，官方口径：支付结果以异步通知或查询接口为准）→ **服务端验签**（异步通知=支付宝公钥 RSA2；演示回环=HMAC）→ 幂等入账 → 按日对账（`/api/pay/reconcile`）。在 `config.json`（参照 `config.json.example` 重命名）填入支付宝**沙箱** appId + 商户私钥并 `pip install pycryptodome` 后，自动切换为真实签名（订单码支付 precreate） |
| `campus` 校园支付网关 | 生产缝 | 学校/班级主体完成支付宝签约后，填网关地址 + appId 即启用（网关实现同样的 order / query / notify 三个接口即可）；密钥只存服务端，不经浏览器 |

> **安全边界（答辩必讲）**：金额一律以「分」为整数存储；订单幂等键为缴费单号（重复通知不重复入账）；**验签一律在服务端完成**，浏览器只展示「已验签」结果；私钥只存服务端 `config.json`。演示模式全程无资金流动，界面明确标注「演示收银台」。

## 四、与宿主系统的契约（三条缝）

| 缝 | 宿主侧 | 本应用侧 |
| --- | --- | --- |
| 身份缝 | `js/pages/payment-host.js` 把登录会话快照按 `{type:'pay:auth', profile:{trusted:true, user}}` 传给 iframe | `PayBridge.loginAsExternal(profile)` 校验 `trusted` 后建会话（镜像 `Auth.loginAsExternal` 语义） |
| 名册缝 | 同一条消息携带 `roster:[{name, studentNo, className}]`（按 `Auth.scopeClassIds` 过滤） | `PayBridge.importRoster()` 按学号幂等 upsert，缺字段计 skipped（镜像 `Store.syncFromEdu`） |
| 网关缝 | 无（宿主不参与支付） | `PAY.GATEWAYS` 预设数组，配置只存本机 `pay_pref_config` |

详细对接文档见 `../集成方案/支付宝缴费接入方案.md`。

## 五、数据口径

- 存储：本应用独占 `pay_*` 前缀键（`pay_fees / pay_orders / pay_ledger / pay_roster / pay_logs / pay_session`），与宿主 `cms_*` 完全隔离；页面不裸调 localStorage，唯一出入口 `PayStore`。
- 金额：**分（整数）**；录入元（两位小数）→ `PayUtils.yuanToFen`；展示 `fenYuan`；公示用大写 `fenCN`（壹贰叁…，已过 12 组用例）。
- 订单状态机：`待支付 → 支付中 → 已支付 → 已核销`（旁路：已退款，仅未核销可退；已核销退款需先在账本做冲销支出）。
- 智能审计：规则引擎**只读**（不改任何业务数据）；结论只存本机偏好 `pay_pref_audit` 供回看；每次运行写一条审计留痕；AI 意见与催缴文案同源（未配置模型自动离线模板）。
- 核销入账：「对账核销」把全部已支付订单核销，并生成**一笔**汇总收入流水（`auto: true`）；全部处理完则费项自动「已结清」。
- 审计：增删改自动写 `pay_logs`（滚动 500 条），公示页与总览可直接引用。

## 六、答辩演示脚本（3 分钟）

1. 宿主登录 `counselor / 123456` → 缴费中心：指出「已接入：班级管理系统」与名册人数——**身份与名册是契约自动接入的**。
2. 发布一笔班费（88.88 元即可，展示分转换与大写）→ 生成应缴名单。
3. 退出，登录 `student / 123456` → 我的缴费 → 去支付：演示收银台（演示二维码水印）→ 模拟支付成功 → 「网关已验签（演示闭环）」→ 电子凭证（大写金额票据）。
4. 回辅导员 → 费项 → 对账核销 → 账本出现自动入账流水 → 公示页生成文稿（壹贰叁编号 + 大写金额）→ 打印预览。
5. （加分项）双击 `启动缴费签名服务.bat` → 设置切「本机签名服务」→ 检测连通 → 再走一遍支付：真实 HTTP 下单 + 异步回调 + 服务端 HMAC 验签 + 按日对账接口。
6. 智能审计：随手记一笔无凭证支出再点「运行审计」——凭证缺失当场被检出并给出证据与建议；「生成 AI 审计意见」出正式公文（未接模型自动用离线模板）。
7. （收尾）设置 → 重置演示数据，一键复位。

## 八、已知边界（诚实声明）

- 演示二维码为伪二维码（稳定可复现、带「演示」水印），**不可真实扫码付款**；真实付款走 `local`（沙箱）或 `campus`（签约）预设。
- `mock` 模式的「已支付」状态在浏览器刷新后不保留（内存态），属演示语义；落库订单不受影响。
- 本应用不做：代管资金、分期、多币种、发票；支付凭证以支付宝账单为准。
- 学生隐私：名册仅含姓名/学号/班级，不含联系方式；催缴名单仅经办人可见。
