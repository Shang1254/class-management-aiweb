# 与学校现有系统集成方案（三条建议的落地路径）

> 评审建议：①对接统一认证实现单点登录；②通过教务接口获取课表成绩（需确认接口权限）；③与学习通互通、或接入校园 AI 助手生态。
>
> 本文逐条给出：**现状（已做/已预留）→ 落地形态与技术要点 → 需要学校提供什么 → 到账后改动量 → 答辩口径 → 边界（不做什么）**。
> 一句话结论：三条都不是"前端能自己搞定"的事，但**接入缝已经全部预留好，且每条都有可离线验证的替代方案**——
> 拿到授权与后端后，改动量都在"配置 + 一个转发接口"量级。

## ① 统一身份认证（单点登录）

**为什么不能在前端做**：CAS 的 `ticket` 必须由**服务端**向认证服务器调 `serviceValidate` 验签后才可信。
浏览器端无法验证票据真伪，把票据校验放在前端等于没有认证；同时本系统的既定边界是**不代登录、不抓取**学校系统。

**已预留的接入缝**（`js/auth.js`）

```js
Auth.SSO                 // { enabled:false, protocol:'CAS 3.0', entry:'https://ca.qcuwh.edu.cn' }
Auth.mapExternalIdentity({ extId, studentNo, username, name })   // 学号/工号 → 本系统用户
Auth.loginAsExternal({ trusted:true, studentNo:'2025990401001' }) // 校验收在服务端，此处只建会话
```

正式对接时序：

```
浏览器 → CAS 登录页（service=后端回调） → 后端收到 ticket
      → 后端 serviceValidate 验签取到学号/工号
      → 后端查本系统账号（或调 /api/users/lookup）
      → 页面调用 Auth.loginAsExternal(profile) → 建立会话
```

**需要学校提供**：CAS 服务地址、`service` 回调白名单、属性字段（学号/工号/姓名字段名）、测试环境与联系人。
**到账后改动量**：只在后端加一个 CAS 回调接口（约 60 行），前端 `Auth` 一行不改；登录页把"账号密码"与"统一认证登录"并列即可。
**答辩口径**："单点登录的**接入缝**已实现（会话建立唯一出口 + 身份映射规则），票据校验按安全要求放在服务端，前端不接触票据——这是有意为之的边界。"
**边界**：不在浏览器保存 CAS 票据、不缓存学校门户会话、不做"模拟学号登录"。

## ② 教务数据对接（课表 / 成绩）

**为什么不能在前端直连**：教务系统接口需要学校授权（IP 白名单 / 接口凭证 / 频率限制），且浏览器跨域无法直连；
把教务处凭证放进前端代码等于公开泄露。

**已预留的契约适配器**（`js/store.js` → `Store.syncFromEdu(payload)`）。约定结构（与后端约定一次即可长期复用）：

```json
{
  "classes":  [{ "name": "计科20252302班", "grade": "2025级", "eduLevel": "本科", "enrollType": "专升本", "studyForm": "全日制" }],
  "students": [{ "name": "张三", "studentNo": "2025990401001", "className": "计科20252302班", "phone": "138…" }],
  "scores":   [{ "studentNo": "2025990401001", "subject": "数据结构", "score": 88, "credit": 4, "nature": "必修",
                 "term": "2025-2026学年第一学期", "examName": "总评" }],
  "timetable":[{ "className": "计科20252302班", "day": 3, "period": "1-2", "course": "数据结构",
                 "teacher": "王建国", "room": "实2-302", "weeks": "1-16周", "term": "2026-2027-1" }]
}
```

特性：**幂等**（按自然键覆盖：班级名 / 学号 / 学号+科目+考试+学期 / 班级+星期+节次+学期）、
**容错**（缺字段的记录计入 `skipped` 而不是写脏数据）、**学期写法兼容**（`2025-2026学年第一学期`、`2025—2026-1` 等）、**全程审计**。

**需要学校提供（建议按此清单去网络信息中心 / 教务处确认）**：

1. 可用接口清单与文档：学生名册、成绩、课表、考试安排（有无 REST/JSON？还是只有导出文件？）
2. 授权形式：IP 白名单 / 接口 Token / 只读库账号？（两者差别很大，前者可零改造后端代理）
3. 数据范围：是否允许按班级维度查询（而非全校）
4. 调用频率与时段限制（避开选课、成绩录入高峰期）
5. 审计要求：是否需要留痕到学校日志、是否要求数据不落地
6. 测试环境与对接联系人、变更通知机制（接口升级如何告知）
7. 若暂不开放接口：**导出文件口径确认**（导出字段、学期字段写法、是否含重修/补考标记）

**到账后改动量**：后端加一个"教务接口 → 约定结构"的转发接口；前端调用 `Store.syncFromEdu(result)`（已可用，含 mock 自测）。
**现在就能演示**：`数据管理 → 教务数据导入`（正方导出的成绩单/课表，含周课表矩阵与"学年+学期"分列），以及本文档附的 mock 调用。
**边界**：不做高频轮询、不抓取 HTML 页面、不绕过任何权限校验。

## ③ 平台融合（学习通 / 校园 AI 助手生态）

**学习通（超星）**：不面向第三方开放公开数据接口，数据互通通常需要**校级合作**（学校与超星的企业级集成）。
因此本系统的策略是"**不依赖、可对话**"：不把功能建立在学习通之上；如果学校后续做了集成，本系统仍按第 ② 条的结构接收数据即可。

**校园 AI 助手生态**（学校"十五五"正在建设的方向）：接入点已经做在 AI 层——

- 新增预设「**校园统一 AI 网关（学校提供）**」：只要学校给出 OpenAI 兼容的网关地址与凭证，填入即用（`js/ai.js` → `PROVIDERS`）。
- 我们这侧对生态友好的三点设计，可以直接写进答辩：
  1. **工具白名单**：AI 只能调用系统内受限的只读函数（`AI.TOOLS`），不会凭空生成数据；
  2. **发送前脱敏 + 可切本地模型**：学生姓名→学生A、手机号打码；不愿出校就切本地 Ollama，数据不出本机；
  3. **静态站点、零运维**：整套系统是纯静态文件，可挂到校园门户子目录或 iframe 嵌入，不新增服务器与数据库。

**需要学校提供**：AI 网关地址与凭证（或"允许调用本地模型"的运维口径）；门户是否开放静态子目录/嵌入位。
**到账后改动量**：改一处配置（地址 + 凭证）；若被门户收录，只需一个静态目录或一行 iframe。
**边界**：不采集任何学生数据出境；不把校园网关凭证写进代码（只存本机、可清空）。

## 答辩口径（三句话概括）

1. **能做的已经做了**：导出文件导入、本地大模型、静态零部署——都不依赖授权即可完整运行。
2. **要授权的已经留好缝**：单点登录的会话入口、教务数据的契约适配器、校园 AI 网关的预设——拿到授权后改动量都在"配置 + 一个转发接口"。
3. **边界是刻意的**：不代登录、不抓取、不绕过权限、不把学生数据传出校；这不是"做不到"，而是**在合规前提下把集成做成可插拔**。
