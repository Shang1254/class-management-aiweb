# Ollama 本地大模型部署指南（Windows）· 班级管理系统接入手册

> 目的：把大模型跑在**本机/校内服务器**上，学生数据完全不离开本校，同时让系统里的
> 「AI 助手」「AI 问答」和三个智能体（值班日报 / 帮扶跟踪 / 我要办事）都能用。
> 依据：Ollama 官方中文文档（ollama.readthedocs.io 的 Windows 页、FAQ 页）与 OpenAI 兼容接口说明，查阅日期 2026 年 10 月。

---

## 一、装什么、要多少资源

| 项目 | 要求（官方口径） |
| --- | --- |
| 系统 | Windows 10 22H2 或更新版本（家庭版/专业版均可） |
| 安装包 | `OllamaSetup.exe`，**无需管理员权限**，默认装在用户目录，二进制占用 ≥ 4 GB |
| 图形驱动 | NVIDIA 驱动 452.39 或更新；AMD Radeon 需装 Radeon 驱动（无独显也可用 CPU 跑小模型） |
| 模型存放 | 默认 `C:\Users\%username%\.ollama\models`，可用环境变量 `OLLAMA_MODELS` 改到空间大的盘 |
| 服务地址 | 默认 `127.0.0.1:11434`（可用 `OLLAMA_HOST` 改绑定地址） |

**模型选择建议**（体积与效果折中）：

| 模型 | 体积级别 | 适用 | 备注 |
| --- | --- | --- | --- |
| `qwen2.5:1.5b` | ~1 GB | 老机器试跑、只做问答 | 质量一般，胜在快 |
| `qwen2.5:3b` | ~2 GB | **教室笔记本 / 8GB 内存推荐** | 中文可用，生成较快 |
| `qwen2.5:7b` | ~5 GB | **16GB 内存或 8GB 显存推荐（默认）** | 中文好，写通知/简报够用 |
| `deepseek-r1:7b` | ~5 GB | 需要推理链的任务 | 会先输出思考过程，更慢 |
| `llama3.1:8b` | ~5 GB | 英文/多语种场景 | 中文不如千问 |

> 判断标准：内存 ≥ 模型体积 × 1.5 为佳；纯 CPU 跑 7B 大约 5—15 token/秒，一段通知需要 20—60 秒，请把演示节奏考虑进去。
> 说明：官网快速入门演示的示例模型是 `gemma4:e2b`（英文向小模型），**中文写通知/简报建议用上面的 qwen2.5 系列**；模型清单以 https://ollama.com/library 为准。

## 二、安装与启动（3 步）

1. **安装**（两个入口任选）：
   - 图形化：打开官网下载页 **https://ollama.com/download** → 切到 **Windows** 标签 → 下载 `OllamaSetup.exe`（直链 https://ollama.com/download/OllamaSetup.exe）→ 双击安装（**无需管理员**）；
   - 命令行一行装：在 **PowerShell** 中执行
     ```powershell
     irm https://ollama.com/install.ps1 | iex
     ```
   官方文档站为 **https://docs.ollama.com**（快速入门页叫"本地运行模型"）；安装完成后 Ollama 会在后台常驻运行。
2. **拉模型**：打开 PowerShell 或 CMD 执行
   ```bat
   ollama pull qwen2.5:7b
   ollama list
   ```
   `ollama list` 能看到模型，说明服务已经就绪；
3. **自检服务**：浏览器打开 `http://127.0.0.1:11434`，或执行
   ```bat
   curl http://127.0.0.1:11434/api/tags
   ```
   返回模型 JSON 即正常。

## 三、关键一步：允许本系统访问（跨域设置）

Ollama 官方 FAQ 明确：**默认只允许来自 `127.0.0.1` 与 `0.0.0.0` 的跨源请求**。
本系统有两种打开方式，处理方式不同：

| 本系统打开方式 | 浏览器发出的来源 | 是否需要额外设置 |
| --- | --- | --- |
| 本地服务器方式（推荐）：`python -m http.server 8080` 后访问 `http://localhost:8080` | `http://localhost:8080` | 一般**不需要**（本机来源默认放行）；若仍报跨域，按下面设置 |
| **双击 index.html（file://）** | `Origin: null` | **必须设置** `OLLAMA_ORIGINS`，否则请求会被拒绝 |

**Windows 上设置环境变量（官方步骤）**：先**退出 Ollama**（右下角托盘图标右键 Quit）→ 在系统设置里搜索"环境变量"→ 打开"编辑账户的环境变量"→ 新建用户变量：

```
变量名：OLLAMA_ORIGINS
变量值：*
```

（也可写得更严：`http://localhost,http://127.0.0.1,file://,null`）
保存后**从开始菜单重新启动 Ollama** 才会生效（官方说明：保存后需重新启动 Ollama 应用）。

可选的两个变量：
- `OLLAMA_MODELS = D:\ollama\models`：把模型挪到大盘；
- `OLLAMA_HOST = 0.0.0.0`：让校内其他机器也能访问（默认可只留 `127.0.0.1`，更安全）。

## 四、在本系统里接上它

1. 登录 → 侧边栏「AI 助手」→「**AI 设置**」；
2. 模型厂商选 **「本地 Ollama（数据不出校内）」**，接口地址保持 `http://localhost:11434/v1`；
3. 点「**读取本机已安装模型**」——系统会列出你 `ollama list` 里的模型（含体积），**点一下名称即填入并保存**；
4. 点「**测试连通**」——出现"连接成功，模型可用"即接入完成；
5. 回到「通知起草 / 值班日报」等标签试一次生成。

> 说明：系统对本机模型**单独放宽了超时（5 分钟）**，并在生成过程中显示"已等待 N 秒"，因为首次调用需要把模型加载进内存。云端模型仍是 60 秒超时。

## 四之二、按本机配置选型（ASUS TUF A15 · R7 6800H + RTX 3060 6GB + 16GB 内存 + 约 565GB 可用空间）

这台机器属于"能跑 7B、跑 3B 很爽"的档次，结论如下：

| 用途 | 推荐模型 | 下载体积（约） | 预计生成速度（经验值） | 说明 |
| --- | --- | --- | --- | --- |
| **日常主用** | `qwen2.5:7b` | 4.7 GB | 10—25 token/秒 | 3060 的 6GB 显存能装下大部分层，中文写作质量够用 |
| **演示/多任务并行** | `qwen2.5:3b` | 1.9 GB | 30—60 token/秒 | 几乎全进显存，响应快；同时开浏览器+IDE 也不卡 |
| 需要推理链 | `deepseek-r1:7b` | 4.7 GB | 8—20 token/秒 | 会先输出思考过程，同样内容更费时间 |
| 不建议 | 14B 及以上（如 `qwen2.5:14b` ≈ 9GB） | 9 GB+ | 2—5 token/秒 | 超出 6GB 显存，大部分层落到 CPU，演示会显得很慢 |

按本系统里的实际功能估算（用 7B）：**通知起草**约 40—70 秒、**值班日报**约 30—50 秒、**出题 3 题**约 40—60 秒；换成 3B 大致减半。系统已把本机模型超时放宽到 5 分钟，并显示"已等待 N 秒"。

**这台机器特别要注意三点**：

1. **混合显卡（AMD 核显 + NVIDIA 独显）**：Ollama 默认走 NVIDIA（CUDA），但个别情况下可能拿不到独显。先在命令行确认：
   ```bat
   nvidia-smi
   ollama ps
   ```
   `ollama ps` 会显示模型是 `100% GPU` 还是 `xx%/xx% CPU/GPU` 分层——最好是前者。若长期跑在 CPU 上，到「设置 → 系统 → 显示 → 图形」把 `ollama.exe` 设为"高性能"。
2. **演示前先"预热"**：模型首次调用要加载进内存（10—60 秒），加载后默认保留 5 分钟。演示前 1 分钟随便生成一次（或命令行 `ollama run qwen2.5:7b 你好`），现场就不用等加载了。想留更久可设环境变量 `OLLAMA_KEEP_ALIVE=30m`。
3. **想省内存就换 3B**：16GB 内存同时开着浏览器、VS Code、钉钉/微信时，7B 会把内存吃得比较紧；演示时建议用 `qwen2.5:3b`，写作质量足够，速度翻倍。

磁盘没问题（剩余约 565GB）：每个模型 2—9GB，装 2—3 个模型一共不到 20GB。

## 四之三、系统内的自检与快速修复（AI 设置页）

打开「AI 助手 → AI 设置」时会**自动真实探测**本机服务，不需要你猜哪里出错：

| 检测结果 | 页面显示 | 你该做什么 |
| --- | --- | --- |
| ✅ 连通 | 绿色徽章「本机模型服务已连通，检测到 N 个模型」+ 三条使用提示（数据不出校/首次加载较慢/演示前预热） | 无需操作，可直接去生成 |
| ❌ 未连通 | 红色徽章「未连接到本机模型服务：<原因>」+ **四步排查指引** | 按 ①②③④ 逐条执行；页面上的「复制启动命令」可直接粘贴到 CMD 运行 |

三个便利按钮：

- **读取本机已安装模型**：列出 `ollama list` 里的模型（名称 + 体积），**点一下即填入并保存**；
- **重新检测服务**：排查过程中随时复检（启动服务后点一下就知道好没好）；
- **复制启动命令**：一键复制下面这段（含模型目录、跨域、30 分钟常驻），粘贴到 CMD 即可起服务：

```bat
set OLLAMA_MODELS=E:\OllamaModels
set OLLAMA_ORIGINS=*
set OLLAMA_KEEP_ALIVE=30m
"%LOCALAPPDATA%\Programs\Ollama\ollama.exe" serve
```

另外，「推荐模型」一行是常用模型的**快捷拉取入口**——点 `qwen2.5:3b` 这类标签，命令 `ollama pull qwen2.5:3b` 就复制到剪贴板了。

## 五、常见问题速查

| 现象 | 原因与处理 |
| --- | --- |
| 提示「无法连接本机模型服务」 | ①Ollama 没启动 → 开始菜单启动 Ollama，`ollama list` 验证；②地址写错 → 必须是 `http://localhost:11434/v1`（带 `/v1`，末尾不加 `/chat/completions`） |
| 浏览器控制台报 CORS / `Origin null is not allowed` | 按第三节设置 `OLLAMA_ORIGINS` 并**重启 Ollama**；或改用 `http://localhost:8080` 方式打开本系统 |
| 提示「尚未安装任何模型」 | 打开命令行执行 `ollama pull qwen2.5:7b`，拉完再点「读取本机已安装模型」 |
| 生成特别慢 / 长时间无响应 | 换小模型（3b/1.5b）、关掉其他占内存的程序；首次调用含加载时间属正常 |
| 报「请求超时」 | 本机模型默认给到 5 分钟；若仍超时，说明模型过大，换小模型或减少题量（出题助手一次别超过 8 题） |
| 磁盘不够 | 设置 `OLLAMA_MODELS` 指向大盘后重新 `ollama pull`（旧模型可删 `C:\Users\你\.ollama\models`） |
| 想给全校用 | 在一台校内服务器上装 Ollama，设 `OLLAMA_HOST=0.0.0.0`，各终端把接口地址改成 `http://服务器IP:11434/v1`；此时务必只在校内网开放，并设置 `OLLAMA_ORIGINS` 限定来源 |

## 六、为什么值得这么做（合规与竞争力）

1. **数据不出校**：学生姓名、成绩、考勤、健康打卡全部只走校内网络，符合个人信息保护与学校数据管理要求——这是学校最在意的一条，答辩与商务沟通都能拿出来讲；
2. **零调用费**：没有 API Key、没有 token 计费，学院批量版可以放心让辅导员天天用；
3. **离线可用**：断网也能生成通知草稿、值班日报与学情简报（系统仍保留"未配置模型时的规则模板兜底"）；
4. **可替换**：同一套界面在「AI 设置」里切换云端/本地，只改一个下拉框，不影响任何业务数据。

## 七、验收清单（部署完照着勾）

- [ ] `ollama list` 能看到至少一个模型（建议 `qwen2.5:7b` 或 `qwen2.5:3b`）；
- [ ] `curl http://127.0.0.1:11434/api/tags` 返回 JSON；
- [ ] 系统「AI 设置」→ 读取本机已安装模型 → 能列出模型并一键填入；
- [ ] 「测试连通」显示连接成功；
- [ ] 通知起草生成一条草稿；值班日报（辅导员账号）生成一份日报；
- [ ] 拔网线再试一次（验证离线兜底仍可用）。
